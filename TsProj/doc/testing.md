# TypeScript 验证规则

## 验证分层

| 层级 | 入口 | 适用变化 |
| --- | --- | --- |
| 类型检查 | `npm.cmd run check` | 所有 TypeScript 源码与类型声明改动 |
| 代码规范 | `npm.cmd run lint` | 新增或修改 TypeScript、配置与声明 |
| 构建 | `npm.cmd run build` | PuerTS 模块加载、导出、编译配置或发布产物变化 |
| 纯逻辑验证 | 项目已有的定点入口；没有入口时先设计可测边界 | ECS、状态机、游戏结算和存档迁移 |
| Unity Play Mode | 从 Boot 进入 Main 并执行受影响流程 | 场景、输入、表现、UI、PuerTS 和 Unity 对象生命周期 |

## 默认准入

- TypeScript 改动至少通过类型检查。
- lint 告警需要判断是否由本次改动引入；不得用全局关闭规则掩盖局部问题。
- 修改 `main.ts` 导出、PuerTS loader、tsconfig 或模块路径时必须构建并确认 `dist/main.js` 可被 Unity 加载。
- 只通过编译不能证明示例行为正确；影响运行时行为时需要执行对应的纯逻辑或 Play Mode 验收。

## 逻辑验证

- 状态机验证关注合法转换、重复调用、非法顺序、初始化失败和幂等释放。
- ECS 验证关注系统顺序、查询结果、延迟销毁、命令消费和同帧可见性。
- 存档验证关注空存档、合法存档、版本升级、损坏数据回退和稳定身份。
- 可以注入的时间、随机源和存储适配应在纯逻辑验证中使用确定性替身。

## Unity 联调清单

- 启动时先进入 Boot，随后进入 Main，运行时只初始化一次。
- 退出 Play Mode 或销毁运行时后，callback、Unity 对象和 PuerTS 环境被完整释放。
- FixedUpdate、Update 和 LateUpdate 的职责与顺序符合运行时契约。
- 输入、UI 和表现只消费权威状态，不产生第二套游戏结论。
- 场景重载、重复进入和异常初始化不会留下重复对象或订阅。

## 测试文件规则

- 不为普通任务静默引入新的测试框架、fixture 体系或批量测试目录。
- 当纯逻辑复杂度需要自动化测试时，先明确测试 owner、运行入口、Unity 依赖隔离和长期维护成本。
- 用户要求的行为使既有验证预期失效时，同步更新有效检查；不删除仍能暴露缺陷的测试。

## 结果记录

- 收尾说明列出实际运行的命令和 Play Mode 场景。
- 无法运行 Unity 或特定平台验证时，明确未验证项和原因，不以静态检查替代其结论。
- 验证揭示的未决技术问题按需进入 `analysis/`，尚未完成的整改进入 `execution/`，不埋在临时日志中。
