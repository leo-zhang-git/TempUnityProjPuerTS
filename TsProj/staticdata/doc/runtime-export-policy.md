# Runtime Export 端裁剪口径

> 本文沉淀 staticdata 表与字段在 client/server 运行时 target 上的端归属判断口径。
> 机制语义见 `../doc/staticdata.md` 与 `schema-design-principles.md` 第 6 节；具体表的端归属以各表 schema 的 `runtimeExport` 声明为准，不在本文枚举。

## 判断口径

端归属按字段职责语义判定：

- **运算字段 → server**：仅服务端权威运算消费的数值、规则、概率、掉落、配方、判定参数。
- **展示 / 资产 / 加载字段 → client**：仅客户端用于展示、资产加载、UI 渲染的文案、图标、prefab 路径、prefab 名、场景表现开关。中文名 / label 在服务端不消费时归 client。
- **两端都解析 → both**：双端运行时都按字段语义读取的字段。

整表端归属在全部字段同端时上升为表级 `runtimeExport`；个别字段与表级不同端时用字段级声明，且必须是表级导出端集合的子集。

字段导出到某端只表示它进入该端 target，不等同于运行时同步协议字段：server 端导出某字段不意味着该字段必须作为同步或协议字段下发，协议字段边界由协议层定义。

## 单端表条件

一张表无任一端的运行时字段消费即可整表单端。**表被对端 ref 指向不构成 both 约束**：ref 完整性校验只在导出到当前端的记录集内做，目标表整表不导出到该端时跳过存在性校验，目标表导出该端但记录缺失才报悬空。

判定步骤：

1. 确认该表在 client、server 各端是否有运行时字段消费方（直接 get/list/require 或经其字段参与运算 / 展示）。
2. 仅单端消费 → 表级单端；该表被对端 ref 指向不影响此判定。
3. 双端都消费 → 表级 `both`，再按字段职责做字段级裁剪。
4. 无任一端运行时消费、仅由非运行时链路（如 Unity 资产打包）使用 → 归该链路所属端。
